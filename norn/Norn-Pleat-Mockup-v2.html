# Pleat: Norns' threads UI, first hardware pass

Implement a visual-only screen for the existing Pleat engine in `D:\src\op-1-tools`. Keep the current engine, knob order, patch format, and plug-in ID. “Norn” is the working visual name, not a request to rename Pleat or change presets.

Use the companion HTML as the visual reference and the downloaded PNG as the source asset. Begin by reading `pleat/plugin/pleat.c`, `pleat/README.md`, `pleat/docs/platform-contract.md`, and the working Ratatoskr renderer and build path. Reuse the repository's existing display hooks, pixel format, asset generation, text drawing, parameter source, and page-lifecycle conventions. Don't bring the browser code or a PNG decoder onto the device.

## Display and art

- Design at 320 × 160 logical pixels. Left controls: x=0–87. Draw a divider at x=87. Keep controls above the art and always legible. Read the mockup's draw loop for exact baselines and track ticks.
- At x=94, y=5 place the supplied 274 × 329 art scaled to 119 × 143. Preserve the silhouettes, braid, hands, and the ivory/black palette. Prepare the reduced asset at build time in whatever form the existing renderer supports (for example, a palette bitmap or scanline runs). Compare at 1× before spending time on further optimization.
- Continue the three colored ribbons from the right edge at x≈213 and y≈62, 95, 119 out to x=310. Keep the hand-side art still. The right-hand ribbons use the artwork colors, not one ribbon per knob: blue #4291FC, green #6CE482, orange #FD8F25. Their first ~18 pixels taper from the painted ends to the usual 1–3 px width.
- Only draw ivory diamonds at actual centerline crossings (sign change between adjacent samples). Suppress near-duplicate diamonds. Use note activity for small traveling highlights if the renderer already has a safe signal. If not, ship a static weave first. Never infer a held note or LFO from a timer.

## Inputs and screen behavior

| Encoder | Waveshaper | Two-op FM | Formant |
| --- | --- | --- | --- |
| Blue | Zone 1 | Zone 2; zone 4 uses FM as a temporary fallback | Zone 3 |
| Green / Harmonics | Curve, neutral at center | Frequency ratio (stepped in DSP) | Second formant interval |
| White / Timbre | Fold | Modulation depth | First formant frequency |
| Orange / Morph | Triangle-to-ramp slope | Bipolar feedback: frequency side on left, OFF at center, phase side on right | Carrier pulse width (low notes; upper notes use the middle shape) |

Blue has four fixed quarters; share or mirror the actual zone rule in `pleat.c` without changing how presets select models. Make zone 4 visually distinct and label it “FM (reserved)” until Wave Terrain lands. Demo percentages are normalized knob positions, not Hz, ratios, or measured feedback. Don't copy the browser's exact percentages as DSP values.

The base marker must never move with modulation. Provide a second hollow marker only if the actual effective value is available safely; otherwise omit it in v1. The demo's LFO is an illustration, not a proposed change to modulation routing. “Hold note” is a browser control only.

For the first animated pass, use the browser geometry as a visual target, not a DSP simulation: Waveshaper uses curvature/fold/slope, FM uses broad warping on the left and smaller ripples on the right with no feedback warp at center, and Formant uses spacing/width cues. The demo’s formant width is an illustrative knob cue (it has no pitch input). If you make it note-aware on hardware, honor the DSP’s high-note behavior. Avoid a redraw or any graphics math from the audio callback. Use the existing UI render path and bounded work; use lookup tables or simpler integer polylines if profiling calls for it.

## Hardware acceptance

1. Screenshot at 1× in all four zones, including both FM zones. No clipping, ghost pixels, or unreadable labels.
2. In FM, sweep orange to min, center, max while holding a note. Verify stable base marker, center “OFF,” distinct left/right visuals. If supported, confirm the hollow marker moves separately under actual LFO.
3. Recall an existing preset and exercise page navigation, retriggering, and polyphony. Verify that model and sound still match the baseline, including the fourth zone.
4. Build with the repo’s normal Pleat target. Run existing host tests and compare device CPU/audio at six voices before and after. Report the asset size and any screen or animation behavior not validated on hardware.

Suggested first implementation: static art and correct live controls, then add the weave transition and note highlights once redraw and audio are verified. No changes to DSP, envelopes, effects, or preset migration are needed.
